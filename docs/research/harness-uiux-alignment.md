# 预览面板 UI/UX 对齐分析与优化清单

日期：2026-09-08。目标：以 DeepSeek Harness 原生界面的文字、列表节奏和控件语言为标准，优化预览面板的阅读与查找体验。

> 当前状态：UX-01–11 已实施并随 [v0.10.0](../verification/releases/v0.10.0/WALKTHROUGH.md)
> 发布；UX-12 真实页面验收未完成。本文保留实施前的问题、数值和原始计划，
> 执行状态以 [根 TODO](../../TODO.md) 为准；后续用户截图见 [侧边栏反馈](sidebar-screenshot-feedback.md)。

## 主要结论

分析时最明显的差距是**导航文字与容器尺度没有一起对齐**：名称多为 13px，文件树仍是 24px 行高，而路径与分组标签低至 10px。界面形成多档细碎的小字，文件列表显得密集，识别与点击都更费力。已有的 12px → 13px 调整改善了一部分，但还没有形成完整的排版规则。

正文已经复用平台 `MarkdownText`，默认正文和标题沿用平台字体变量。没有证据支持更换整套字体家族；首先应修正字号层级、行盒、留白、路径表达，以及真实存在的主题颜色问题。

### 需要优先处理的颜色问题

对固定 Harness 源码搜索，下列变量没有定义：`--dsw-alias-fill-secondary`、`--dsw-alias-fill-tertiary`、`--dsw-alias-fill-primary`、`--dsw-alias-accent`、`--dsw-alias-bg-float`、`--dsw-alias-font-mono`、`--dsh-alias-label-primary`。带有效 fallback 的声明与完全没有 fallback 的声明应逐项区分，不能一律视为已经失效。

当前分段选中态为：背景 `var(--dsw-alias-accent, var(--dsw-alias-label-primary))`，文字 `#fff`。基线没有 `accent`；深色主题的 `label-primary` 为浅色，所以背景与白字接近。[R2 深色截图](../verification/r2-acceptance/r2-13-conflict-dark-en.png)中的 Edit 选中项已呈现该现象。当前源码仍保留相同组合，需在当前构建复验。

这也说明旧走查的“深色可用”与“视觉细节全部合格”是不同证据。后续验收需覆盖具体交互状态，而不只确认面板底色变深。

## 原始执行计划与验收条件

优先级：P0 = 文字/状态可见性缺陷；P1 = 本轮主要体验对齐；P2 = 后续精修。S = 单一局部样式或组件；M = 多个区域/状态联动。工作量为相对大小，不是工期承诺。下列勾选保留分析阶段的计划状态，已实施项目与剩余验收见根 TODO。

### P0：恢复清晰的交互状态

- [ ] **UX-01 · 统一有效颜色变量与分段选中态（M）**
  - 修改：[styles.ts][P1]。按语义映射到基线真实存在的 hover、active、背景、文本、品牌变量；修正搜索文字变量前缀；选中态使用成对背景/前景变量。同步检查树当前预览目标、快捷入口、大纲当前节、焦点和禁用态。
  - 验收：浅色/深色下，预览和编辑两种选中态的文字均可读；hover、当前预览目标和键盘焦点均可辨；计算样式不再依赖未定义且无有效 fallback 的颜色。必要小号文字对比度达到 4.5:1，按实际背景合成计算，不凭截图观感判定。[W1]

### P1：字体、节奏与可操作性

- [ ] **UX-02 · 建立导航文字层级（S）**
  - 修改：[styles.ts][P1]。主名称和面板标题 14px / 20px，辅助路径 12px / 18px，分组标签 12–13px；统一使用平台字体家族。常规名称 400 字重，仅当前预览目标或必要标题使用 500。
  - 验收：文件树、快捷入口、搜索结果与大纲的同级文字规格一致；必要名称/路径不再使用 10px；中英文、数字与标点无垂直裁切。保留平台正文随字号设置变化的行为。

- [ ] **UX-03 · 同步调整行高与间距（M）**
  - 修改：[styles.ts][P1]。单行以 32px 行盒为目标，目录可对齐 34px；含路径的双行条目以至少 48px 起步。内容边距以 12px、行内边距以 8px 起步，图文 gap 统一到 6px；分组间距先用 12px，组标题与条目间 4px。
  - 验收：同类行同高；名称基线、图标中心线和悬停背景边界整齐；五级嵌套不挤掉文档名。24px → 32px 会减少同屏可见行数，应与 UX-05/07 联合验收，不能靠缩回小字解决溢出。
  - 取舍：早期[浏览脸调研](workspace-browser-ux.md)曾为窄面板选择 24px 紧凑行高；本轮依据用户“以 Harness 为标准”的要求调整默认密度。

- [ ] **UX-04 · 统一图标、搜索与点击区域（M）**
  - 修改：[WorkspaceBrowser.tsx][P2]、[PreviewOverlay.tsx][P3]、[styles.ts][P1]。文件夹/文档和常用操作优先使用 primitives 的 16px 图标，替换同一区域混用的 emoji 与手绘图形；常用图标按钮按 28×28px 设计，展开器至少提供 24×24px 的矩形命中区域；常驻搜索采用 32px 高的统一规格。
  - 验收：搜索、清空、刷新在同一中心线上；相邻命中区不重叠；点击展开器不会打开文档；点击名称仍保留原行为；Tab、方向键、Enter 可用。尺寸按实际命中区域检查，不能以 SVG 大小代替。[W2]

- [ ] **UX-05 · 优先展示文档名与可区分的路径（M）**
  - 修改：[WorkspaceBrowser.tsx][P2]、[PreviewOverlay.tsx][P3]、[styles.ts][P1]。快捷入口与搜索结果使用工作区相对展示路径；窄空间将路径放第二行，优先保留能区分同名文档的父目录。头部折叠中间路径段，优先保障末段文档名，完整路径仍可获取。
  - 验收：`alpha/report.md`、`beta/report.md`、深层 `alpha/nested/report.md` 在收窄后仍可区分；长中文名和英文名有明确省略方式。路径格式化仅影响展示，不改预览目标、阅读记录键或 Host 的路径权威；只有绝对路径且缺少工作区根信息时不得猜测相对路径。

- [ ] **UX-06 · 整理头部对齐与操作层级（M）**
  - 修改：[PreviewOverlay.tsx][P3]、[styles.ts][P1]。文档身份、预览/编辑、文档操作、面板操作使用明确分组间距；统一控件高度。保留“低频操作收进 ⋯、保存/关闭直接可达”的原则，图标扩大后重新验算折叠断点。
  - 验收：面板宽 360、559、560、639、640、900px 及放大档，长标题和英文文案不挤出保存/关闭；保存中与禁用态可辨。
  - 待决事实：现有未提交改动将面板改为从顶部覆盖宿主头部，而当前契约仍要求避开实测的头部条带。此项应确定最终停靠规则并同步契约与验收；本分析不代为反转已有改动，也不据历史截图判定新位置不合格。

- [ ] **UX-07 · 让快捷区与窄导航都保留有效信息（M）**
  - 修改：[WorkspaceBrowser.tsx][P2]、[preferences.ts][P5]、[styles.ts][P1]。当前导航默认宽 148px，快捷入口最多 5 条产出 + 3 条最近阅读，另有继续阅读入口。放大文字前先处理路径双行、分组留白和窄空间降级；在文档与导航并排时评估较宽的初始导航空间。
  - 验收：同时出现全部快捷条目时，搜索仍能在约定的常用高度中直接发现和到达；148px / 220px / 320px 导航宽度分别留图核对；默认空间只影响未手动选择的用户，手动偏好不被覆盖。
  - 约束：当前回合产出、最近阅读与继续阅读保持各自语义。若采用折叠分组、改变默认条数或移动搜索位置，先在任务内写清目标行为并同步对应契约，不把这些变化隐藏在“间距调整”里。

- [ ] **UX-08 · 对齐编辑脸的字体与深色细节（M）**
  - 修改：[editor.tsx][P4]、[styles.ts][P1]。使用平台已定义的代码字体变量，明确编辑区、行号沟槽、查找框、选择区和光标的主题色；保存状态与匹配计数采用一致且可读的辅助文字规格。
  - 验收：当前构建的深色编辑脸无突兀浅色沟槽；行号、选区、光标和搜索匹配均可读；从查看脸进入编辑脸时无意外的字体尺寸跳变；输入、查找、保存和未保存守卫行为保持正确。

### P2：阅读与表面精修

- [ ] **UX-09 · 用同文档校准正文节奏与阅读尺寸（S）**
  - 修改候选：[styles.ts][P1]。继续由 `MarkdownText` 管正文和标题；对照普通与放大档的 760/940px 阅读尺寸、16/18px 段距和 32/36px 标题上距，评估额外留白是否确有收益。
  - 验收：同一 Markdown、相同有效正文宽度、相同 Harness 字号设置下，正文 computed font 与行高一致；再比较自然面板宽度下的阅读体验。覆盖长中文、英文、列表嵌套、表格、代码和公式；长块仍仅在自身横向滚动。
  - 约束：放大档更宽且更宽松属于当前契约；若决定统一段距，应同步修改契约，不能无记录移除既定行为。

- [ ] **UX-10 · 收敛边框、阴影与低频信息占位（S）**
  - 修改候选：[styles.ts][P1]、[PreviewOverlay.tsx][P3]。评估平台浮层投影、边框和背景变量，减轻当前固定大阴影；同类列表行采用一致圆角。版本号已经位于路径提示，评估取消仅显示版本的常驻底栏，将版本集中到帮助信息。
  - 验收：浅色下层级边界清楚，深色下依靠边框仍可分辨预览面板；列表、搜索、分段控件不会被强行套成一种圆角；保存状态持续可见，版本信息仍有明确查询入口。

- [ ] **UX-11 · 补齐缩放与滚动时的视觉稳定性（M）**
  - 修改候选：[styles.ts][P1]、[PreviewOverlay.tsx][P3]、[WorkspaceBrowser.tsx][P2]。核查滚动条出现时的列宽变化、窄面板换脸、路径提示的键盘可达性、失效/空/加载状态的文字层级。
  - 验收：100%、125%、200% 浏览器缩放下，关闭/保存/返回工作区浏览可达；悬停与滚动条出现不造成名称左右跳动；搜索中、完整空结果、结果不完整、失败仍清晰可区分；位置恢复与手动偏好保持稳定。
