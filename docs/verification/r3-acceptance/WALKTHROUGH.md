## 联合走查发现并修复的缺陷

**搜索遍历伪造 FsTarget（已修复并回归锁定）**：首版 search 的 BFS 以
`{displayPath}` 字符串重建目录目标，违背真实 fs 层 FsTarget
`{targetKey, displayPath}` 契约——真实实例上每次 listDir 失败，整场搜索
落为「结果不完整 · 部分目录无法读取」+ 零命中（jsdom fake 未检查形状故未
拦截）。修复：frontier 全程携带 fs 自己的 FsTarget（root 来自 resolve、
子项来自 entry.target）；测试侧将 host-harness 的 listDir fake 加固为强制
契约形状（先红后绿），修复后重打包重装实测四同名文档全部命中。这正是
真实实例走查的价值所在。

## 持续使用候选指标定义（保留观察，不预填数据）

- **候选指标**：在有下一次文档任务的用户中，**再次选择预览面板**完成该任务
  的比例（再次选择 = 该文档任务的首个打开动作经本面板任一入口：chip /
  预览文档动作 / 工作区文档 / 搜索 / 快捷入口 / 继续阅读）。
- 记录维度：观察期（建议 ≥2 周）、期内样本数（有文档任务的用户数）、有资格
  再次使用的人数（期内用过面板 ≥1 次）、分子（其中下一任务仍选择面板）。
- 本轮基线事实：固定任务走查中「找到未展开深层同名文档」从 ≥5 次手动展开
  降为 2 次操作（输入+点击，约 0.9s）；恢复阅读保持 1 次操作。**样本 = 本
  次走查 1 人 1 轮，不构成留存或提升结论**；不新增遥测平台，后续人工记录。

## 已知限制与留观

1. 搜索匹配文档**名称**（不区分大小写子串），目录名不参与匹配；同名分辨
   依赖结果中的路径列（首版语义，见 spec #20 决策 11）。
2. 未滚动过的短文档不产生阅读记录，因此不进入「最近阅读」——阅读记录是
   位置事实（#25 契约），不是访问日志。
3. 失效阅读记录在被新阅读覆盖前仍占据「继续阅读」席位（点击得到明确失败
   态 + 返回浏览；R2 轮已留观条目，行为未变）。
4. 搜索失败态与迟到响应仅 jsdom/host 层可强制覆盖（真实页面需破坏后端才能
   触发）；走查记录以自动化套件为凭。
5. 结果上限默认 200（实测 205 份样本诚实截断 + 说明）；真实 DSH 工作区
   （几十至低百份文档、浅树）远达不到该界，实测依据已随 #30 提交记录。
