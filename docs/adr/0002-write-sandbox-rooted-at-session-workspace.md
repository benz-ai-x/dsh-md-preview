# 面板写入的沙箱策略以会话工作区为根

沙箱化的 fs 后端对未显式携带策略的写入按全局 standing root 围栏,而那不是会话
的工作区——于是每一次面板保存在沙箱部署上都被 `FS_SANDBOX_DENIED` 拒绝(0.2.2
之前的实际故障)。写入因此显式携带 per-call 策略 `workspace-write`,根为该会话
的工作目录,与 harness 工具层"会话 cwd 永远作为 workspaceRoot"的惯例一致;后端
仍以规范化路径复检围栏,插件自身的 contains 判断只是第一道。

## Consequences

- 面板写入永远不可能落到会话工作区之外,与读取权威同界。
- 若部署整体要求只读,禁用插件行是唯一开关;写入本身不因部署只读而静默降级。
