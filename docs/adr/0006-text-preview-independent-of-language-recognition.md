# 文本预览准入与语言识别分别决定

日期：2026-09-08。状态：已接受的设计边界，尚未实现。

实施更新（2026-09-09）：[#39](https://github.com/benz-ai-x/dsh-md-preview/issues/39)
已实现基本文本准入、统一入口、只读原文与手动内容刷新；下文格式化、语法高亮和
分段读取仍由后续票实施，不能以本次原文呈现代替其验收。

读取复用固定基线 `ctx.fs.streamText` 的 fatal UTF-8 解码与二进制判定，Host 按
UTF-8 字节限制保留内容，超限立即结束迭代；`FS_NOT_TEXT` 统一映射
`md-preview/not-text`，不解析错误消息来猜测二进制或非法编码。成功响应显式携带
`kind` 与 `editable`；Markdown 配置只控制编辑资格，新增文本不开放写入。
`previewExtensions` 作为兼容字段保留，但不再充当文本读取白名单。

用户要求无扩展名和未知语言的文本也能预览，因此已知扩展名不再是文本预览的
必要条件：Host 确认工作区文件可作为文本读取后准入，语言与格式识别用于选择
相应的预览美化或纯文本回退。新增文本保持只读，Markdown 的既有编辑资格和保存守卫独立保留；
路径范围与读取限额仍由 Host 和文件服务裁决。

在准入之外，按类型明确呈现要求：JSON、XML 均须支持缩进、换行、语法高亮和
结构折叠，压缩内容也应可清晰阅读。纯文本回退承担兜底职责，不能代替有效
JSON、XML 的格式化预览验收。格式化不写回源文件，解析与排版方案在实施阶段确定。

分段读取遵循已确认的一致性规则：检测到文件指纹变化（包括追加日志）时，保留
已加载内容，暂停续读并提示内容刷新；刷新后从头读取。读者已接受持续追加的日志
也使用这一规则，以避免在同一次续读中拼接不同版本的内容。

仅维护扩展名集合会遗漏无扩展名文件，也让读取能力依赖语言支持清单。分开两者
可持续覆盖文本文件，但需要明确编码、非文本判定及失败行为；这些细节与分段
读取的限额、续读协议在实施阶段细化。已确认的分段阅读方式见
[设计与实施 TODO](../../TODO.md#多格式预览设计与实施)。各入口中的文件候选始终不是
读取授权，打开时需要重新裁决；工作区名称搜索保持不读取正文的既有边界。
